# FROST — Roadmap

## Done

- [x] **Phase 1 — Foundations** (`frost-build.sh`): arch detection, pacman tuning, base system, dev toolchain, `/opt/frost/` scaffold, colored failsafe logging with rollback
- [x] **Phase 2 — AUR & environment** (`frost-phase2.sh`): trusted AUR helper build (throwaway unprivileged user), idempotent default dotfiles, `frost-cli`
- [x] **Phase 3 — System & distribution** (`frost-phase3.sh`): hostname/locale/timezone/fstab, bootloader (systemd-boot/grub), standard sudo user, optional desktop/server profile, archiso live-ISO profile generation
- [x] End-to-end validation in a real VM: bootstrap → chroot provisioning → reboot → login, with `sudo`/`docker`/`sshd` confirmed working
- [x] Project docs: README, ARCHITECTURE, this roadmap, MIT license
- [x] **Boot & Aesthetic pack** (`frost-branding.sh`): GRUB theme, Plymouth splash, `/etc/motd`, zsh aliases — **VM-validated**: installed cleanly via `frost-deploy.sh` chaining. GRUB/Plymouth *visual* rendering (does the theme actually look right on real boot) still unconfirmed — installing without error isn't the same as looking correct.
- [x] **Security & Hacking Tools pack** (`frost-security.sh`): pentest toolkit (nmap/wireshark/metasploit/hashcat/aircrack-ng/hydra/sqlmap/john/nikto/gobuster/nuclei/burpsuite/w3af), ufw firewall, VPN templates, SSH hardening + fail2ban, optional Tor — **VM-validated**: every tool installed (official + AUR via the delegated user, burpsuite's ~700MB jar + JDK dependency included), `redis`'s one transient AUR network failure handled gracefully (logged, didn't abort the run) exactly as designed
- [x] **Gaming & Dev Stack pack** (`frost-gaming.sh`): Steam/Lutris/Heroic/GameMode/MangoHud, GPU auto-detection (nvidia/amd/intel/virtual) + driver install + NVIDIA modeset tweak, full dev stack (rust/go/java/postgres/redis/mongo/vscode/jetbrains), sysctl + RAM disk + sensors tuning, `frost --mode gaming|dev` wired into frost-cli — **VM-validated**: Steam's full multilib tree installed, `postgresql`'s `initdb` step confirmed running, `fancontrol` correctly refused to auto-configure and printed the manual `pwmconfig` instructions as designed. GPU was detected as `amd` on VirtualBox's virtual adapter rather than falling into the `virtual` branch — worth a closer look.
- [x] **Deployment & Auto-Update pack** (`frost-deploy.sh` + `frost-update.sh`/`frost-status.sh`/`frost-uninstall.sh` + 4 systemd units): master orchestrator with pre-flight checks, checkpoints/`--resume`, per-phase (not cross-phase) rollback; opt-in-only auto-updates; a local-only (never external) daily security audit; hourly cleanup; background health monitoring; `/etc/frost/frost.conf` with `bash -n` validation; conservative opt-in-flagged uninstall with a pre-removal backup — **VM-validated end to end**: a real `check_root` bug (see ARCHITECTURE.md Lesson 4) killed the chain mid-run, `--resume` correctly picked up from the last good checkpoint after the fix, and the full 7-phase chain finished with `🎉 FROST SYSTEM DEPLOYED SUCCESSFULLY!`. `frost-uninstall.sh` itself still untested.
- [x] **FROST OS Desktop** (`frost-desktop.sh`): GNOME Shell + Mutter re-skinned in FROST Iceblue — a themed desktop, deliberately not a from-scratch custom shell (see [DESKTOP.README.md](DESKTOP.README.md) for why that scope call was made). Real GTK4/Libadwaita CSS theme, a small `frost-shell` GNOME Shell extension (Steam Mode toggle, easter egg), Dash to Dock + Blur my Shell configured (not reimplemented), a generated hex-faceted wallpaper, and a published mockup gallery covering all 7 requested screens. **VM-validated**: GDM login works; the FROST wallpaper, GTK theme, and all three GNOME Shell extensions confirmed live and rendering. Getting `frost-shell@frost-os` itself running took fixing three real bugs (stale `shell-version`, missing `settings-schema`, wrong Quick Settings API contract — ARCHITECTURE.md Lesson 7) — now `State: ACTIVE`, Steam Mode toggle and the FROST panel menu both confirmed working live. A follow-on **signature-identity pass** added hex-faceted accents (quick settings/notifications/dash corners), a stronger cyan focus glow on windows and floating chrome, and a custom FROST hex panel icon — all within GNOME Shell's real capabilities, after reality-checking a much larger from-scratch-shell brief back down to this scope (see chat history / DESKTOP.README.md's scope note).
- [x] **Contribution guide.** [CONTRIBUTING.md](CONTRIBUTING.md) — commit message convention (emoji + type, full body posted to Discord) and the safety-model rules new code must follow.

## Next up

- [ ] **Bundle the AUR helper into the live ISO.** Right now `mkarchiso` only pulls from official repos, so `yay`/`paru`/VSCode stay a post-install step even on the built ISO. Standing up a small local package repo (`repo-add` + a custom `[frost]` entry in the ISO's `pacman.conf`) would let the ISO ship with the AUR helper preinstalled, without ever building AUR packages *inside* the image untracked.
- [ ] **CI boot test.** Automate what the VM validation pass did by hand: a GitHub Actions job that runs all three phases against a QEMU disk image headlessly and asserts it reaches a login prompt. Catches regressions like the `IFS` array-join bug automatically instead of relying on someone noticing in a manual test.
- [ ] **`frost-cli update` for the distro's own scripts**, not just packages — a `frost self-update` that re-syncs `/opt/frost/scripts/` from a pinned release.
- [ ] **`frost-cli uninstall` / rollback for Phase 2/3 changes** after the fact (not just mid-run failure rollback) — e.g. `frost-cli undo-profile` to cleanly remove a `desktop` profile's packages and re-enable a `server` one.
- [ ] **Desktop profile polish.** Current `desktop` profile (Xorg + i3 + lightdm + pipewire) is intentionally bare-bones. Worth a second, deliberately-configured pass: default i3 config with sane keybindings, a status bar, a picom config tuned for VMs vs. real hardware.
- [ ] **Disk encryption (LUKS) as an opt-in Phase 3 flag.** Currently FROST never touches partitioning/encryption — this would stay opt-in and explicit, consistent with "never guess the disk layout."
- [ ] **Secure Boot support** for the systemd-boot path (signed kernel/bootloader), for users who need it.
- [ ] **ARM validation.** The architecture-detection branch for `aarch64`/`armv7h` has never been run against real ARM hardware or a matching QEMU target — only reasoned about. Needs an actual test pass the way x86_64 got one.
- [ ] **Non-`en_US`/`UTC` presets.** `--locale`/`--timezone` already work for any valid value; a documented set of common presets (`fr_FR.UTF-8` + `Europe/Paris`, etc.) would save typing for non-US users.
- [ ] **Confirm the GRUB/Plymouth theme actually looks right on a real boot** — installed without error (see above), but nobody's rebooted the VM and looked yet. Reboot off the installed disk (not the live ISO) and screenshot the boot sequence.
- [ ] **FROST panel hex icon is hard to see** — the button is confirmed present and clickable (opens the FROST OS menu), but `icons/frost-hex.svg` at 16px doesn't read well against the dark panel even after thickening its strokes once. Needs another visual pass (bolder/filled glyph, maybe a solid background chip).
- [ ] **Confirm the `Ctrl+Super+E` easter egg fires** — Steam Mode toggle and the FROST menu are now confirmed working; the keybinding itself hasn't been separately tested.
- [ ] **Re-verify the `#dashtodockContainer` hex-accent CSS** added in the signature-identity pass — dash-to-dock's internal class names are the least stable part of `stylesheet.css` (see its own header comment) and weren't re-checked with the same rigor as the rest of the file.
- [ ] **Double-check GPU detection on VirtualBox** — `frost-gaming.sh` reported `amd` for VirtualBox's virtual display adapter rather than the intended `virtual` branch; find out what string its `lspci` output actually contains and fix the detection regex if it's a false match rather than genuinely AMD-related.
- [ ] **`frost-uninstall.sh`** still has zero real-world runs — do one against this same VM once the above is confirmed, and check the disk afterward.

## Explicitly out of scope (for now)

- A graphical installer / TUI — FROST is scripts-first by design (see [ARCHITECTURE.md](ARCHITECTURE.md#why-not-just-use-archinstall))
- Automatic disk partitioning — FROST never guesses a disk layout; you partition, FROST installs
- A rolling "FROST release" separate from upstream Arch — FROST is a provisioning layer on top of Arch, not a fork
