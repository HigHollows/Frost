# Contributing to FROST

## Commit messages

Every commit follows:

```
<emoji> <type>: <description>
```

| Emoji | Type | Use for |
|---|---|---|
| ✨ | `feat` | a new feature |
| 🐛 | `fix` | a bug fix |
| ♻️ | `refactor` | refactoring, no behavior change |
| 📚 | `docs` | documentation only |
| 🧪 | `test` | tests |
| 🔧 | `chore` | maintenance (deps, config, tooling) |
| 🚀 | `deploy` | deployment/release |
| ⚡ | `perf` | performance improvement |
| 🎨 | `style` | visual/style change, no logic change |
| 🔒 | `security` | security fix or hardening |

For anything beyond a trivial change, add a detailed body under the subject:

```
✨ feat: add authentication system

- what changed, concretely (files/modules touched)
- why it was built this way (design decisions worth recording)
- what was fixed along the way
- how it was verified — real testing, not just "should work"
```

**No vague messages.** `update`, `changes`, `fix`, `stuff`, `wip` are not acceptable subjects, even for small commits — say what actually changed.

**Keep the full message.** The project's local `post-commit` hook posts the *entire* commit message (not just the subject) to the team Discord channel, so write the body as something worth reading there, not just for `git log`.

A local `commit-msg` hook warns (non-blocking) if a subject doesn't match the `<emoji> <type>: <description>` shape — it won't stop your commit, just reminds you.

## Code conventions

Before touching any of the `frost-*.sh` scripts, read [ARCHITECTURE.md](ARCHITECTURE.md) — in particular:

- Never join a package/argument list with `"${arr[*]}"` (or embed `"${arr[@]}"` mid-string) into a `chroot_exec` command string — `IFS` is set to `$'\n\t'` at the top of every script, so array joins silently break. Use a plain space-separated string instead.
- Every state-changing step should go through the `run()` wrapper so `--dry-run` stays accurate.
- Anything that edits a config file (`pacman.conf`, `sudoers`, `fstab`, `mkinitcpio.conf`, …) must back it up first and register it so `trap ERR` rollback can restore it.
- Validate any new user-supplied flag with a regex allowlist before it gets interpolated into a `chroot_exec` string.

## Branding assets

Every image under `branding/` is generated by `branding/tools/generate_assets.py` (Pillow) — never hand-edit a PNG in place; change the generator and re-run it, so the asset stays reproducible from source.
